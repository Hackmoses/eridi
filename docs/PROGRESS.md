- 2026-11-03 Scan speed (after first real use): files with no text extractor (photos, videos, archives) are indexed by name without being read, which also means renames of those aren't detected as moves. - 2026-11-03 Parallel scans: reading and extracting run in worker processes (`settings.scan_workers`, 0 = one per CPU core minus one, max 16; spawn context on every OS), while one process writes the index. A crashed worker falls back to in-process reading. Scans use their own SQLite connection and don't hold the service lock, so search and notes keep working during a long scan (the app's background scan no longer freezes it). A first scan of a fresh index is a normal scan plus version-log restore and full record load, not a drop-and-rebuild. Snapshots skip fsync (cache; a lost one only loses a diff) and version-log lines are written once per batch with one fsync. Progress shows listing, then "Reading X: n of N · about T left". Benchmark, same 1,910-file folder on 4 cores: 22.6 s originally → 9.7 s single process → 4.3 s parallel.
