- 2026-11-03 M0: CI green on all six jobs (macOS, Windows, Linux × Python 3.12, 3.13). Waiting on the hands-on check on a personal Mac and Windows machine. Test PDFs are generated by a tiny built-in writer, so no PDF library is needed for fixtures. `new_ulid()` is strictly increasing within a process so entries written in the same millisecond keep their order.
- 2026-11-03 M1.1: the reader requires non-empty `text` only for `note` and `decision` (other kinds may leave it empty). Unknown fields are kept on nested objects (author, subjects, change, links, project) as well as the entry. `make_entry()` creates validated entries and lowercases tags.
- 2026-11-03 M1.4: view rules beyond the plan: competing corrections → newest wins; a retracted correction still hides what it replaced (delete means gone); retracting a tombstone restores its target; references to newer IDs are ignored, which rules out cycles. Documented in `core/record/views.py`.
- 2026-11-03 M1.5: default size limit is 25 MB (so the plan's 50 MB file is skipped). Added a `Root` model to `core/models.py`; config keeps unknown keys when saving.
- 2026-11-03 M2.2: folder links are never followed (even inside the root, to avoid loops and duplicates); file links are followed only when they resolve inside the root. `.eridiignore` is read from the root folder only. `changes_since` for local folders reports files modified after the cursor time; removals come from comparing listings in the scanner.
- 2026-11-03 M2.3: added status `name_only` (unknown types) and `too_large` alongside `ok`/`needs_ocr`/`cloud_document`/`error`. Default size limit 25 MB. Also reads `.docm`, `.xlsm`, `.pptm`, `.tsv`, `.markdown` and pptx speaker notes.
- 2026-11-03 M3.1: index schema adds `files.title`, `files.extract_status` and `entries.state` (current/superseded/retracted) to the ARCHITECTURE.md tables; file IDs are integers internal to the index. A damaged index file is deleted and recreated.
- 2026-11-03 M3.3: all entries are indexed with a `state`; only current, non-tombstone entries are searchable. `entries_fts.summary` also holds subject file paths and project names, so notes are findable by file name. Full reconcile runs on first load and then at most hourly (`sync_records(full=True)` forces it); it also drops entries whose files disappeared. Added `entries.change_to_text_sha256` for M4's pending changes.
- 2026-11-03 M3.4: the plan's "blocking buffer" test needs the docx protocol, which contains "blocking" but not "buffer". So search returns hits with every word first, then, if fewer than `limit`, hits with some of the words (`SearchHit.matched_all=False`). The last bare word is a prefix match (3+ characters). Snippet highlights use control characters `\x02`/`\x03`; render with `segments()` or `snippet_with()`. Added `core/index/ingest.py` (list → read → extract → index one root), used by search tests and rebuild; M4's scanner builds on it.
- 2026-11-03 M3.5: files that go missing leave the full-text index (row kept, status `missing`), otherwise BM25 statistics differ from a rebuild. Equivalence covers search results, present files, entries and their states, subjects, projects and roots. **Plan gap for M4 (agreed, now in PLAN.md M4.1):** `text_versions` written by scans can't be rebuilt from storage plus the record (a rebuild only sees current text), which breaks the "index is disposable" rule once diffs depend on it. Proposal: in M4.1, keep a small append-only per-file version log next to the snapshots in app data (`snapshots/versions.jsonl`: root, path, text sha, first seen), and have rebuild reload it.
- 2026-11-03 M4.1: the version log also records moves (`kind: "move"`), so history follows renamed files through a rebuild; merged versions keep the earliest `first_seen`. Eviction treats each file's current text as referenced too, so the next diff always has its "before". Index schema is now version 2 (`file_moves` table).
- 2026-11-03 M4.2: the scanner replaces M3's `core/index/ingest.py` (rebuild now scans a fresh index, then replays the version log). A file whose bytes are unchanged after a touch is hashed but not extracted. A read error on a known file keeps its previous text instead of counting as a change. An unreachable root marks nothing missing. A deleted file that comes back is reported as new. Added extraction status `online_only`.
- 2026-11-03 M4.3: a pending change is also cleared by an entry whose subject's `text_sha256` is the file's current text (a note attached to that version), not only by `change.to_text_sha256`; a retracted explanation brings the change back. Dismissal keys are `<root>:<from sha>:<to sha>` (first 16 hex each), so they survive renames. Config gains `dismissed_changes`, `[mcp] allow_writes` and `settings.scan_interval_minutes` (for M6/M7).
- 2026-11-03 M4.4: `Eridi` also has `init`, `update_root`, `remove_root`, `resolve_file`/`find_files` (M5.3's path / partial name / ID lookup lives here so every interface shares it), `get_entry`, `retract` and `dismiss`. A file's ID is `<root_id>:<path>`. `add_note(file=…)` attaches the file's pending change automatically. `.eridi-root.json` is written only with `mark_folder=True`. Eridi's own record and app-data folders are ignored if they sit inside a root. A fresh or upgraded index is rebuilt on the first scan. Agent-written entries are authored `<agent> (for <user>)` with `kind: agent`.
